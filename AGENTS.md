# Назначение репозитория

Это самостоятельная русскоязычная учебная методичка по SystemVerilog: от основ
цифрового описания и синтезируемого RTL до проверки, моделирования и средств связи
с внешним кодом. Пользователь планирует учиться и пользоваться ею как справочником.
Нужно объяснять язык, а не ограничиваться оглавлением или перечнем конструкций.

Первоначальный запрос: изучить корневой `PLAN.md` (оглавление книги «Язык
SystemVerilog для синтеза», 2022), самостоятельно перестроить темы в логическом
порядке, написать весь материал с нуля, учесть изменения после 2022 года,
разместить главы в иерархии Markdown, дать активные ссылки на весь план в
`README.md` и реализовать сборку единого итогового PDF. Ключевые договорённости
и сведения о проекте должны поддерживаться в этом файле.

## Источники и границы

- `PLAN.md` — пользовательский первичный материал. Не изменять и не удалять.
- Текст и примеры методички создаются самостоятельно; не восстанавливать текст
  книги по оглавлению и не копировать большие фрагменты стандартов.
- Нормативная база — IEEE 1800-2023. Проверено 2026-09-23: карточка IEEE считает
  его активным, дата публикации 2024-02-28. Стандарт доступен через IEEE GET.
- Различать правила языка, переносимое RTL, возможности конкретного инструмента
  и инженерные рекомендации. Не объявлять поддержку стандарта поддержкой синтеза.
- UVM — отдельная библиотека/методология (IEEE 1800.2), а не часть синтаксиса SV.
- Это учебное изложение всех основных областей языка, а не замена нормативному
  LRM, его полной грамматике, таблицам VPI и документации каждого синтезатора.
- Новшества 2023 года отмечать явно. У изменяемых сведений указывать первичный
  источник, версию и дату проверки; не приписывать старые конструкции новой версии.

## Структура и порядок чтения

- `book.json` — единственный источник порядка частей, глав и приложений.
- `README.md` — входная точка, команды и автоматически обновляемое оглавление.
- `docs/01-foundations` — модель аппаратуры, лексика, модули, симуляция.
- `docs/02-data` — типы, выражения, агрегаты, массивы, приведения.
- `docs/03-language` — присваивания, управление, подпрограммы, пакеты, генерация,
  интерфейсы, препроцессор.
- `docs/04-rtl` — комбинационная и последовательностная логика, память, автоматы,
  тактирование и сквозной FIFO.
- `docs/05-verification` — тестбенчи, процессы, классы, random, SVA, coverage, DPI.
- `docs/06-modeling` — примитивы, задержки, конфигурации, стандарты и инструменты.
- `docs/appendices` — синтезируемость, справочник, упражнения с ответами,
  соответствие исходному плану, источники и предметный указатель.
- `examples` — автономные исходники, эталонный FIFO и самопроверяющийся тестбенч.
- `tools` — сборщик, проверки текста/ссылок/примеров и тесты инфраструктуры.
- `dist/systemverilog.pdf` — итоговая методичка; `dist/systemverilog.md` — единый
  Markdown. Артефакты пересобираются из исходников; PDF не править вручную.

## Редакционные требования

1. Одна глава — один Markdown с одним заголовком первого уровня; подразделы H2/H3.
2. Объяснять смысл, синтаксис, поведение, применение и типичные ошибки.
3. Помечать контекст примеров: полноценная единица компиляции, фрагмент RTL,
   фрагмент тестбенча или намеренно ошибочный пример.
4. Для аппаратных конструкций объяснять получаемую схему и ограничения синтеза.
5. Для временной семантики указывать момент выборки и обновления, избегать гонок.
6. В каждой главе есть упражнение; ответы собраны в приложении.
7. Внутренние ссылки — относительные Markdown-ссылки. Без зависимых от ОС путей.
8. Не оставлять заглушки вместо запрошенных разделов. Если поддержка или результат
   проверки неизвестны, фиксировать это прямо; компиляция не равна симуляции.

## Сборка и проверка

Python 3.10+, зависимости в `requirements.txt` и `requirements-dev.txt`.
Рекомендуется локальная `.venv`; не требуются TeX, Pandoc или Word.
Команды ниже выполняются Python из виртуального окружения:

```text
python tools/book.py toc
python tools/map_plan.py
python tools/book.py check
python tools/book.py build
python tools/check_sv.py
python tools/check_pdf.py
python tools/simulate.py
python -m unittest discover -s tools/tests -v
```

Сборщик использует markdown-it-py и ReportLab, встраивает доступные кириллические
TTF-шрифты, создаёт оглавление, закладки и ссылки внутри PDF. На Windows используются
Arial/Consolas, на Linux DejaVu. Пути к шрифтам можно передать явно.
Проверять отсутствие пропущенных глав, корректность локальных ссылок и якорей,
компиляцию самостоятельных примеров, читаемость кириллицы и кода в PDF.
Доступные команды симуляции и фактические результаты описываются в `VALIDATION.md`.
После изменений обновлять оглавление, PDF и отчёт проверки вместе с текстом.

## Текущее состояние

Созданы 33 главы и 6 приложений; все 362 нумерованных пункта PLAN.md отражены
в таблице соответствия. Есть полный RTL FIFO и самопроверяющийся тест для
глубин 1/3/8 и ширин 1/8/13. На 2026-09-23 пять наборов прошли компиляцию
slang 11.0.0, FIFO прошёл симуляцию Icarus Verilog 13.0. Результаты остальных
runtime-проверок не заявляются. Подробности — `VALIDATION.md`.

`tools/map_plan.py` воспроизводит приложение D. Полные листинги FIFO и тестбенча
в главе 22 проверяются на совпадение с автономными файлами в `examples`.
Справочник 248 ключевых слов сверяется с набором токенов установленного slang.
`tools/simulate.py` требует отдельно установленный Icarus либо явные пути
`--iverilog`/`--vvp`. Служебная локальная установка находится в игнорируемом build.
GitHub Actions выполняет проверки, симуляцию и сборку PDF; публикация исходников
или отправка изменений в remote не входят в выполненную локальную работу.
