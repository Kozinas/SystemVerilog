# 01. Аппаратное мышление и устройство языка

SystemVerilog описывает одновременно структуру цифровой системы, её поведение
во времени и окружение, которое проверяет это поведение. Один файл может содержать
формулу сумматора, регистр с тактовым входом и класс генератора транзакций.
Синтаксическая корректность всех трёх описаний не означает, что все они превращаются
в транзисторы одним и тем же инструментом.

## От программы к схеме

В обычной программе выражение вычисляется, когда до него дошёл поток исполнения.
В аппаратном описании `assign y = a & b;` задаёт постоянно действующую связь:
при изменении входов пересчитывается выход. Два таких присваивания существуют
параллельно. Порядок их записи в файле не создаёт последовательность тактов.

Регистр хранит состояние между событиями. Комбинационная схема вычисляет результат
по текущим входам. Если представить устройство как граф, регистры будут границами
между участками комбинационной логики. Задержка реального участка определяется
технологией и разводкой; запись `+` сама по себе не задаёт наносекунды.

Полный небольшой модуль синтезируемого RTL:

```systemverilog
module enabled_register (
  input  logic       clk, rst_n, en,
  input  logic [7:0] d,
  output logic [7:0] q
);
  always_ff @(posedge clk or negedge rst_n)
    if (!rst_n) q <= '0;
    else if (en) q <= d;
endmodule
```

Это восемь триггеров с асинхронным сбросом и разрешением записи. Отсутствие `else`
после проверки `en` означает сохранение состояния. Условия синтеза enable могут
дать специальный вход триггера или мультиплексор перед ним. Позже мы разберём,
почему здесь используется `<=`, а не `=`.

## Три этапа обработки

1. **Компиляция:** препроцессор раскрывает директивы, компилятор разбирает синтаксис,
   имена и типы. Пакет должен быть доступен до использования его объявлений.
2. **Элаборация:** выбирается верхний модуль, создаются экземпляры, подставляются
   параметры, раскрывается `generate`, проверяются соединения.
3. **Моделирование:** процессы работают в дискретном времени по правилам планировщика.

Синтез использует элаборированное описание допустимого подмножества языка и строит
логическую сеть. После оптимизации и технологического отображения можно получить
netlist. Размещение, трассировка и статический временной анализ — следующие этапы
проектирования, а не операторы SystemVerilog.

## Уровни описания и элементы проекта

| Элемент | Что выражает | Обычное применение |
| --- | --- | --- |
| `module` | Иерархический аппаратный блок | RTL, netlist, тестбенч |
| `interface` | Группа сигналов и протокол доступа | Соединение блоков |
| `package` | Общие типы, константы, подпрограммы | Организация исходников |
| `primitive` | Пользовательский примитив с таблицей | Модели ячеек |
| `program` | Проверяющий процесс с Reactive-семантикой | Специализированные тестбенчи |
| `checker` | Повторно используемый набор проверок | Assertions |
| `config` | Выбор библиотечных реализаций | Элаборация проекта |

Поведенческая модель описывает «что получается», структурная — «из чего собрано».
RTL описывает передачу и преобразование данных между регистрами. Это не три разных
языка: один модуль может соединять экземпляры, содержать формулы и тактовые процессы.

## История и маршрут обучения

SystemVerilog развивает Verilog, добавляя типы, специализированные процессы RTL,
интерфейсы и средства проверки. Редакция IEEE 1800-2009 объединила описание базового
Verilog и расширений SystemVerilog; последующие редакции уточняли и расширяли язык.
В этой методичке основа — [IEEE 1800-2023](https://standards.ieee.org/ieee/1800/7743/).
Сведения о переходе с 2017 на 2023 собраны в
[главе 33](../06-modeling/33-tools-standards.md).

Сначала изучайте обычные модули и значения, затем временную семантику и RTL.
Классы и constrained random полезны после того, как вы способны объяснить,
на каком фронте устройство принимает вход и когда его выход становится доступен.
Наличие большого тестбенча не исправляет неопределённый контракт устройства.
