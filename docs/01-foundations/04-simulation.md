# 04. Время и планировщик симуляции

Моделирование — обработка очередей событий. Симулятор перескакивает к следующему
моменту, в котором есть работа, и может многократно пересчитывать процессы внутри
одного значения времени. Такое продвижение без изменения времени часто называют
дельта-циклами. Оно позволяет сигналу пройти цепочку комбинационных зависимостей.

## Единица времени и точность

В модуле или интерфейсе объявления времени помещают до остальных элементов:

```systemverilog
module time_demo;
  timeunit 1ns;
  timeprecision 1ps;
  logic clk = 0;
  always #5ns clk = ~clk;
  initial begin
    #12.345ns;
    $display("time=%0t", $realtime);
    $finish;
  end
endmodule
```

`timeunit` задаёт масштаб безразмерных задержек, `timeprecision` — точность
квантования задержек данного контекста. Глобальная точность симуляции учитывает
самую мелкую требуемую точность проекта. `$time` возвращает целое время,
`$realtime` — вещественное; формат `%t` дополнительно зависит от `$timeformat`.
Директива `` `timescale `` поддерживается для старых исходников, но её действие
зависит от порядка текста. Локальные объявления делают модель понятнее.

## Области одного временного слота

Ниже — рабочая карта, а не обещание одного линейного прохода. События могут
возвращать обработку к более ранним областям того же временного слота.

| Область | Характерная работа |
| --- | --- |
| Preponed | Выборка значений для конкурентных assertions |
| Active | Выполнение обычных модульных процессов, blocking assignments |
| Inactive | Возобновление модульных процессов после `#0` |
| NBA | Обновления от неблокирующих присваиваний |
| Observed | Оценка конкурентных свойств по выбранным значениям |
| Reactive | Процессы `program`, действия конкурентных assertions |
| Re-Inactive, Re-NBA | Аналогичные очереди для реактивного набора |
| Postponed | `$strobe`, `$monitor`, наблюдение установившихся значений |

Между этими областями стандарт задаёт и точки взаимодействия PLI:
Pre-Active, Pre-NBA, Post-NBA, Pre-Observed, Post-Observed, Pre-Re-NBA,
Post-Re-NBA, Pre-Postponed. Для повседневного RTL важнее понимать выборку,
Active и NBA, чем запоминать API-области.

## Неблокирующее присваивание

Внутри тактового процесса правая часть `q <= d;` вычисляется при выполнении
оператора; обновление `q` планируется в NBA. Поэтому два регистра могут
одновременно принять старые значения друг друга:

```systemverilog
// Фрагмент внутри модуля; a и b объявлены logic.
always_ff @(posedge clk) begin
  a <= b;
  b <= a;
end
```

Если перед фронтом `a=1`, `b=0`, после NBA получим `a=0`, `b=1`.
С блокирующим `=` во втором присваивании уже читалось бы новое `a`.
Порядок разных процессов в Active не является способом задать приоритет.

## Гонки и наблюдение

Если DUT читает `data` на `posedge clk`, а тестбенч блокирующим присваиванием
меняет `data` на том же фронте, результат может зависеть от порядка выполнения
процессов. Переставлять строки между файлами — ненадёжное «исправление».
Простое учебное решение — подавать стимулы на противоположном фронте, а результат
наблюдать после обновления состояния. Для сложных протоколов служит `clocking`.

`#0` не означает «дождаться всех NBA»: Inactive предшествует NBA. `$display`
в тактовом процессе может вывести старое значение, а `$strobe` — установившееся
в конце временного слота. Проверки должны заранее определять, какое значение им нужно.

Задержки `#` описывают модель и тестбенч. В обычном RTL они не превращаются
в заданный физический интервал. Для задержки на N тактов нужны N состояний
или регистров и спецификация частоты.

## Упражнение 04

До фронта `a=2`, `b=7`. Определите значения после `a <= b; b <= a;` и после
`a = b; b = a;`. Объясните, почему `#0` перед проверкой не гарантирует чтение
обновлённого неблокирующим присваиванием регистра.
