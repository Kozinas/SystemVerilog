# 05. Сети, переменные и встроенные типы

Тип данных описывает допустимые значения и операции. Вид объекта определяет,
как значение хранится или получается от драйверов. Эти измерения независимы:
`wire logic [7:0] bus;` — сеть с четырёхсостоянийным векторным типом данных,
а `logic [7:0] state;` — переменная того же типа данных.

## Сеть и переменная

Сеть (`wire`, `tri` и другие) отражает значения драйверов, используя функцию
разрешения. У обычной `wire` два равносильных противоречащих драйвера дают X.
Переменная хранит последнее присвоенное значение; она не выполняет электрическое
разрешение нескольких независимых записей. Множественные записи могут быть
запрещены правилами конструкции либо создавать гонку.

```systemverilog
// Объявления внутри модуля.
wire logic [7:0] resolved_bus;
logic [7:0] register_value;
bit ready_model;
```

`reg` — историческое имя четырёхсостоянийного типа переменной. Оно не гарантирует
получение триггера: триггер выводится из поведения процесса. В новом коде обычно
используют `logic`, сохраняя явный `wire` там, где существенна сетевая семантика.
`var` явно указывает переменную. `uwire` помогает обнаруживать несколько драйверов.

## Встроенные числовые типы

| Тип | Бит | Состояния | Знаковость по умолчанию |
| --- | --- | --- | --- |
| `bit` | 1 | 2 | unsigned |
| `logic`, `reg` | 1 | 4 | unsigned |
| `byte` | 8 | 2 | signed |
| `shortint` | 16 | 2 | signed |
| `int` | 32 | 2 | signed |
| `longint` | 64 | 2 | signed |
| `integer` | 32 | 4 | signed |
| `time` | 64 | 4 | unsigned |

`int unsigned` удобен для неотрицательных счётчиков тестбенча и параметров.
Для регистра заданной аппаратной ширины предпочтительнее `logic [W-1:0]`.
`real`/`realtime` соответствуют double-precision представлению, `shortreal` —
single-precision. Они применяются в моделях; для синтеза вещественной арифметики
требуется явно поддерживаемый инструментом путь.

Преобразование X/Z в двухсостоянийный тип заменяет их нулями. Поэтому `bit`
на наблюдаемом выходе DUT способен скрыть неисправность сброса. Экономия памяти
тестбенча не должна менять смысл проверки.

## Векторы и выбор частей

```systemverilog
logic [15:0] word;
logic [0:15] forward_word;
logic [3:0] nibble;
// Фрагмент процесса:
// nibble = word[7:4];
// nibble = word[base +: 4];
```

В упакованном диапазоне левый индекс обозначает старшую позицию независимо от
численного порядка индексов. Обычный part-select требует постоянных границ.
Indexed part-select `base +: width` или `base -: width` допускает переменную
базу и постоянную ширину. Выбор бита и части packed-вектора сам по себе
беззнаковый, даже если исходный вектор был signed.

Выход за границы — ошибка проектирования. Для четырёхсостоянийного чтения
неопределённого бита получится X; детали агрегатов зависят от типа элемента.
Не следует строить функциональность на поведении некорректного индекса.

## Область видимости, время жизни, инициализация

Область видимости отвечает на вопрос «где доступно имя», время жизни — «как долго
существует объект». Переменные модуля живут всю симуляцию. Автоматические
локальные переменные создаются заново для каждого вызова подпрограммы или входа
в соответствующую область. Статические сохраняются между вызовами.

Инициализация статической переменной при объявлении происходит один раз,
а автоматической — при каждом создании. `logic q = 0;` не эквивалентно
сбросу, действующему при каждом включении системы. Поддержка начального
состояния аппаратурой зависит от FPGA/ASIC и синтезатора.

## Константы и прочие типы

`parameter` можно переопределить при создании экземпляра, `localparam` — нельзя.
`const` запрещает последующие изменения переменной по правилам const, но
не превращает её автоматически в элаборационную константу. `specparam`
используется в моделях задержек. `$` имеет специальный смысл неограниченной
границы в разрешённых контекстах и не является универсальным числом «бесконечность».

`string` хранит последовательность байтов переменной длины; `chandle` — непрозрачный
указатель для DPI; `event` — средство синхронизации. Агрегатные типы объединяют
несколько значений; singular-типы противопоставляются распакованным структурам,
объединениям и массивам. Интегральные типы допускают битовую интерпретацию,
включая packed-структуры и packed-массивы.
