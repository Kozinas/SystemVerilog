# 07. typedef, enum, структуры и объединения

Пользовательский тип делает намерение частью интерфейса. Вместо передачи
безымянного набора битов можно передавать команду с полями адреса, данных и признака
записи. При этом packed-представление остаётся конечным вектором для аппаратуры.

## typedef и перечисления

`typedef` вводит имя типа, а не создаёт переменную. Именованные определения
лучше переиспользовать из пакета: повторно написанные похожие агрегаты не всегда
имеют ту же идентичность типов.

```systemverilog
package command_pkg;
  typedef logic [15:0] word_t;
  typedef enum logic [1:0] {
    IDLE = 2'b00, READ = 2'b01, WRITE = 2'b10, ERROR = 2'b11
  } operation_t;
  typedef struct packed {
    operation_t op;
    logic [7:0] address;
    word_t data;
  } command_t;
endpackage
```

Базовый тип enum задаёт ширину, знаковость и поддержку X/Z. Без явного базового
типа используется `int`. Если метки не получили значения, первая начинается
с нуля, следующие увеличиваются. Значения должны помещаться в базовом типе и
удовлетворять правилам уникальности. Диапазонные формы имён генерируют несколько
меток; для протоколов явная запись значений обычно нагляднее.

Enum даёт проверку совместимости при присваивании. Произвольный вектор нельзя
считать допустимым состоянием только потому, что его ширина совпала.
`operation_t'(bits)` выполняет статическое приведение и не проверяет членство.
`$cast(op, bits)` может проверить допустимость; в функции его возвращаемое
значение надо обработать.

Методы `first()`, `last()`, `next()`, `prev()`, `num()`, `name()` помогают
обходить перечисление и печатать символические имена. `next()` не является
универсальным описанием желаемого перехода конечного автомата: переход зависит
от протокола, а не от расположения меток.

## Структуры и assignment patterns

В `struct packed` поля образуют непрерывный вектор; первое объявленное поле
занимает старшие биты. Все поля должны быть допустимыми packed-элементами.
Для структуры выше `$bits(command_t)` равен 26. По умолчанию packed-структура
unsigned; `signed` у всего агрегата меняет интерпретацию целого вектора.

Фрагмент внутри модуля с импортом пакета:

```systemverilog
import command_pkg::*;
command_t cmd;
always_comb begin
  cmd = '{op: IDLE, address: '0, data: '0};
end
```

`'{...}` — assignment pattern, учитывающий тип и поля приёмника. `{...}` —
конкатенация, собирающая элементы по своим правилам. Смешивать их по внешнему
сходству нельзя. `'{default: '0}` удобно для заполнения подходящего агрегата,
но строгие поля enum могут потребовать явной допустимой метки.

У распакованной `struct` поля могут иметь разнородные типы, например `string`
и динамический массив. Она не обязана быть одним аппаратным вектором.
Присваивание структуры копирует значения её полей; если поле является handle
объекта, копируется handle, а не весь объект. Структуры передаются через порты
и аргументы подпрограмм с учётом совместимости типов.

## Объединения

`union` предоставляет несколько представлений одного хранилища. В обычном
`union packed` члены имеют одинаковую битовую ширину:

```systemverilog
typedef union packed {
  logic [31:0] word;
  logic [3:0][7:0] bytes;
} word_view_t;
```

Запись `u.word = 32'h11223344;` означает, что `u.bytes[3]` — `8'h11` при
указанных диапазонах. Это определяется порядком packed-битов, а не endian
процессора, запускающего симулятор. Распакованные объединения имеют другие
правила хранения и проверки типов; их не следует применять как переносимый RTL.

`union tagged` хранит сведения о выбранном варианте. Конструктор
`tagged Some value` задаёт вариант, а сопоставление с образцом через `matches`
позволяет проверить тег и связать полезную нагрузку с локальным именем.
Такой тип удобен для моделей вариантов сообщения: «данные» или «ошибка».
Чтение неактивного варианта ограничено правилами языка. Синтез и поддержку
pattern matching нужно проверять отдельно.

В 2023 появился `union soft packed`, допускающий разные размеры членов;
это специальное дополнение с правилами перекрытия битов, а не разрешение
разноразмерных членов в прежнем обычном packed union.
Подробности совместимости — [глава 33](../06-modeling/33-tools-standards.md).
