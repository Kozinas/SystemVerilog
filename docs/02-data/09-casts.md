# 09. Совместимость и приведение типов

Совпадение битовых размеров ещё не означает совместимости типов. Язык различает
идентичные, эквивалентные, совместимые по присваиванию и совместимые по приведению
типы. Особенно заметны различия у enum, распакованных агрегатов, классов и `ref`.

## Проверять интерфейс, а не только биты

Для обычных интегральных присваиваний возможны расширение и усечение. При
присваивании enum действует более строгая типизация. При передаче `ref` подпрограмма
получает доступ к исходному объекту, поэтому компилятор не может просто создать
временную конвертированную копию, как для обычного `input`.

Совместимость сетей учитывает вид и тип данных, а для пользовательских `nettype`
существенны и правила разрешения. Совместимость класса связана с наследованием;
одинаковые поля двух несвязанных классов не делают handles взаимозаменяемыми.

`$typename(expr)` помогает при диагностике, но строковое имя типа не следует
использовать как переносимый ключ для определения его семантики. `type(expr)`
получает тип выражения там, где синтаксис ожидает тип, например при объявлении
типового параметра. Это не вычисление значения объекта.

## Статические приведения

```systemverilog
typedef logic signed [15:0] sample_t;
sample_t sample;
logic [7:0] raw;
// Фрагменты выражений:
// sample = sample_t'($signed(raw));
// count = int'(short_value);
// masked = 8'(wide_value);
```

`T'(expr)` преобразует к типу T. `N'(expr)` задаёт размер, сохраняя правила
знаковости исходного выражения. `signed'(expr)` и `unsigned'(expr)` меняют
знаковую трактовку. `$signed`/`$unsigned` выполняют близкую задачу для
интегральных выражений без самостоятельного расширения ширины.

В приведении `sample_t'($signed(raw))` сначала 8-битный `raw` трактуется
как signed, затем расширяется до signed 16 бит. Если сразу привести unsigned
`raw` к более широкому типу, отрицательное значение не появится из намерения автора.

Обычное преобразование real к целому с помощью интегрального приведения округляет
к ближайшему целому, половины — от нуля. `$rtoi` усекает дробную часть к нулю.
`$realtobits` и `$bitstoreal` переинтерпретируют битовое представление real,
а не превращают числовое 1.0 в целочисленное 1. Для shortreal существуют
`$shortrealtobits` и `$bitstoshortreal`.

## Динамический $cast

Полная единица тестбенча:

```systemverilog
module enum_cast_demo;
  typedef enum logic [1:0] {STOP=0, GO=1} mode_t;
  mode_t mode = STOP;
  logic [1:0] bits = 2;
  initial begin
    if (!$cast(mode, bits))
      $display("Rejected mode; previous value is %s", mode.name());
  end
endmodule
```

При неудаче функциональная форма `$cast` возвращает 0 и не меняет назначение.
Статическая запись `mode_t'(bits)` не выполняла бы эту проверку членства enum.
Для классов `$cast` проверяет, можно ли handle базового класса безопасно
рассматривать как handle нужного производного класса. Проверка не создаёт объект.

## Битовые потоки и упаковка

Bit-stream cast преобразует допустимые агрегаты через последовательность битов.
Для фиксированных представлений нужны согласованные размеры; для динамических
приёмников действуют дополнительные правила определения размера. Это полезно
для сериализации тестовых пакетов, но не заменяет описание формата протокола.

Определите порядок полей, индексов и байтов до написания упаковки. Packed-структура
имеет заданный порядок битов; динамическая структура C по DPI может иметь padding
и иную ABI. Нельзя объявлять их совместимыми по внешнему сходству объявлений.
Потоковые операторы позволяют явно задать направление и размер блока перестановки.

## Типичные ошибки

Частые причины дефекта: cast добавлен после переполнения; unsigned part-select
используется как отрицательное число; результат `$cast` игнорируется; X теряется
при преобразовании в `bit`; enum с незаконным кодом воспринимается как проверенный.
Приведение должно объяснять намерение, а не просто подавлять диагностику компилятора.
