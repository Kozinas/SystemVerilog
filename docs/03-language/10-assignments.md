# 10. Присваивания и процессы RTL

Присваивание описывает либо постоянно действующий драйвер, либо действие процесса.
Из выбора оператора и событийного управления складывается модель комбинационной
логики, защёлки или триггера. Имя типа `logic` само по себе этого выбора не делает.

## Непрерывное присваивание

```systemverilog
module mux2 (
  input wire a, b, select,
  output wire y
);
  assign y = select ? b : a;
endmodule
```

`assign` — элемент модуля, а не строка внутри `always`. Правая часть пересчитывается
при изменении зависимостей. Непрерывное присваивание переменной также допускается
правилами SystemVerilog с ограничениями на драйверы; это не разрешение одновременно
записывать тот же объект из независимых процессов.

## Blocking и nonblocking

`=` обновляет левую часть в ходе выполнения оператора. Следующая строка того же
последовательного процесса видит обновлённое значение. `<=` вычисляет правую часть
сейчас, а обновление планирует в NBA. Блокирующий оператор не блокирует всю
симуляцию: слово относится к продолжению конкретного процесса.

Обычное правило RTL: комбинационные вычисления — `=`, состояния на фронте — `<=`.
Временные локальные вычисления в тактовом процессе возможны и с `=`, если они
имеют ясный смысл и не становятся разделяемым состоянием. В одном сигнале
смешивать blocking и nonblocking не следует.

## always_comb, always_latch, always_ff

```systemverilog
// Фрагмент модуля: next_value и q имеют одинаковый тип.
always_comb begin
  next_value = q;
  if (load) next_value = data;
  else if (step) next_value = q + 1'b1;
end

always_ff @(posedge clk)
  if (reset) q <= '0;
  else       q <= next_value;
```

`always_comb` запускается один раз в начале моделирования, учитывает зависимости
читаемых выражений и вызываемых функций и запрещает временное ожидание. Переменные,
которые он записывает, не должны записываться другими процессами. У старого
`always @*` есть отличия в правилах чувствительности и начального запуска.

В `always_comb` не стоит читать временную переменную до её вычисления:
`c = b; b = a;` может оставить `c` равным прежнему `b`. Чувствительность не делает
блок итерационным решателем: значения, записываемые внутри блока, имеют особые
правила исключения из неявной чувствительности. Сначала вычисляйте промежуточные
значения, затем используйте их.

`always_latch` выражает намерение получить прозрачную защёлку: при закрытом
разрешении состояние сохраняется. `always_ff` выражает тактовое состояние,
допускает одно событийное управление и ограничивает дополнительные временные
управления и записи из других процессов. Список событий в одном `@(...)`
может содержать такт и асинхронный сброс.

Обычный `always` остаётся универсальным процессом. `always` без событий/задержек
или другого блокирования может создать бесконечный цикл нулевого времени.
`initial` выполняется один раз, `final` — при завершении симуляции и не должен
потреблять модельное время.

## Неполные присваивания

В комбинационном блоке каждый выход должен получить значение на любом пути.
Иначе модель сохраняет прежнее значение, что означает память. Значения по умолчанию
в начале блока помогают показать полный контракт. Присваивание X как default
в синтезе может рассматриваться как don't-care и дать непредсказуемое поведение
для фактически встретившегося кода; для управляющих выходов лучше безопасное значение.

## Задержки внутри и перед присваиванием

`#5 a = b;` ждёт, затем читает `b`. `a = #5 b;` читает `b` сейчас, блокирует
процесс и обновляет позже. `a <= #5 b;` читает сейчас, планирует обновление
и позволяет процессу продолжиться. Эти формы служат моделированию; они не задают
пятибитный или пятиступенчатый аппаратный буфер.

Наследуемые процедурные `assign/deassign` и `force/release` имеют специальные
правила переопределения значений. `force` полезен при диагностике тестбенча,
но способен скрыть реальный драйвер. После `release` переменная и сеть возвращаются
к обычному поведению по разным правилам: сеть пересчитывается по драйверам,
переменная может ждать следующей процедурной записи. Это не переносимый RTL.
