# 11. Условия, выбор и циклы

Процедурные операторы выбирают действия внутри процесса. В RTL они описывают
логику выбора и повторяющуюся структуру вычисления. Последовательность строк
в `begin ... end` не означает последовательность тактов.

## if и case

`if (cond)` выполняет ветвь при истинном условии. Нулевое или неопределённое
булево значение не выбирает эту ветвь; иначе выполняется `else`, если он есть.
Цепочка `if/else if` задаёт приоритет: первая выполненная проверка завершает выбор.

Обычный `case` сравнивает значения с учётом X/Z по правилам точного сопоставления.
`casez` допускает Z/`?` как wildcard, `casex` — ещё и X. Маскирование неизвестности
на входе способно скрыть дефект сброса, поэтому `casex` в управляющем RTL опасен.
`case (...) inside` позволяет задавать диапазоны и наборы с асимметричными
правилами wildcard сопоставления.

```systemverilog
// Фрагмент комбинационного процесса.
always_comb begin
  result = '0;
  case (opcode)
    2'b00: result = a & b;
    2'b01: result = a | b;
    2'b10: result = a ^ b;
    default: result = '0;
  endcase
end
```

Наличие `default` явно задаёт поведение для прочих значений. Оно не обнаруживает
ошибочный код само по себе; для этого нужна отдельная проверка входного контракта.

## unique, unique0, priority

| Квалификатор | Проверяемое намерение |
| --- | --- |
| `unique` | Не более одной подходящей ветви; без default/else ожидается совпадение |
| `unique0` | Не более одной подходящей ветви; отсутствие совпадения разрешено |
| `priority` | Порядок ветвей существенен; без default/else ожидается совпадение |

Они могут порождать диагностику симулятора и давать синтезатору основания для
оптимизации. Это обещание автора, которое должно быть правдой. Если оставшиеся
входные комбинации на практике возникают, оптимизированная схема не обязана
повторять удобное поведение исходной неполной модели.

Исторические директивы/комментарии `full_case`, `parallel_case` задают подобные
подсказки отдельным синтезаторам, но обычный симулятор может их не учитывать.
Получается риск расхождения симуляции и схемы. Явный полный код, стандартные
квалификаторы и assertions лучше делают контракт проверяемым.

## Циклы

`for` содержит инициализацию, условие и шаг. `repeat(N)` выполняет тело N раз.
`foreach` обходит индексы массива. `while` проверяет условие до тела,
`do ... while` — после, `forever` повторяет без условия остановки.

```systemverilog
// Фрагмент комбинационного суммирования фиксированных элементов.
always_comb begin
  total = '0;
  for (int i = 0; i < 4; i++)
    total = total + extended_input[i];
end
```

Такой цикл описывает вычисление суммы в одном комбинационном интервале.
Для суммирования за четыре такта нужны индекс-регистр и тактовый процесс.
Синтезатор должен суметь ограничить/развернуть цикл; бесконечный `while`
без временного управления не становится автоматически конечным автоматом.

`break` завершает ближайший цикл, `continue` переходит к следующей итерации.
`return` завершает подпрограмму, а в функции может вернуть значение.
`disable` именованного блока имеет более широкие исторические применения;
использование для управления несколькими активациями требует осторожности.

`begin : name ... end : name` создаёт именованную область. Имена полезны для
диагностики и иерархических ссылок. Объявления локальных переменных размещаются
в начале соответствующего блока до исполняемых операторов.
