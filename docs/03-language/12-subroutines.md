# 12. Функции, задачи и время жизни

Функция вычисляет результат без потребления модельного времени. Задача описывает
процедуру, которая может ждать события или задержки. Это различие относится
к семантике симуляции, а не к скорости физического вычисления после синтеза.

## Функции

```systemverilog
function automatic logic [7:0] saturating_inc(input logic [7:0] value);
  if (&value) return value;
  return value + 8'd1;
endfunction
```

Это объявление можно поместить в модуль или пакет. Вызов в комбинационном
выражении описывает проверку максимума и инкремент. Функция не может выполнять
блокирующее временное управление; косвенные вызовы также должны соблюдать
ограничения функций. `function void` не возвращает полезного значения,
но сохраняет ограничения на время.

Результат можно присвоить имени функции или вернуть через `return`.
Явные типы аргументов и результата предотвращают случайные однобитные/неверно
унаследованные объявления. Функция может иметь `output`, `inout`, `ref`,
но побочные эффекты затрудняют использование как чистого выражения.

## Задачи и аргументы

```systemverilog
// Фрагмент тестбенча; clk, valid, payload объявлены в модуле.
task automatic drive_word(input logic [7:0] value);
  @(negedge clk);
  valid = 1'b1;
  payload = value;
  @(negedge clk);
  valid = 1'b0;
endtask
```

`input` получает значение при входе, `output` передаёт результат при выходе,
`inout` копирует при входе и выходе. `ref` связывает формальный аргумент
с исходной переменной: изменения видны во время выполнения. `const ref`
разрешает чтение без копирования, запрещая изменение через этот аргумент.
Ссылочные аргументы требуют автоматического времени жизни подпрограммы и
совместимого типа реального объекта; выражение вроде `a+b` не заменяет переменную.

Можно задавать значения аргументов по умолчанию и вызывать по имени:
`configure(.timeout(20), .enable(1));`. Это облегчает развитие интерфейса,
но направление `input` и тип желательно повторять, если их наследование
от предыдущего аргумента может запутать читателя.

## Static и automatic

У обычных подпрограмм модулей по умолчанию статическое время жизни, если
контекст не задаёт другое. У методов класса — автоматическое. `automatic`
создаёт отдельные аргументы и локальные переменные для каждого активного вызова.
Без этого параллельные вызовы задачи могут перезаписывать общие локальные данные.

Статическая локальная переменная сохраняет значение между вызовами. Инициализация
при объявлении не повторяется с каждым вызовом. Для рекурсивного вычисления
обычно нужно `automatic`; даже корректная рекурсивная функция не обязательно
поддерживается синтезатором при динамической глубине рекурсии.

В 2023 `ref static` позволяет явно потребовать, чтобы фактический аргумент
имел статическое время жизни. Это важно для операций, чьё действие переживает
обычный вызов, и не означает «сделать локальную копию статической».
Режим языка и ограничения конкретного применения проверяются отдельно.

## Константные функции и параметры

Константная функция вызывается при элаборации, если её аргументы и тело
удовлетворяют соответствующим ограничениям. Она подходит для расчёта разрядностей
и таблиц. Время симуляции, текущее значение входа и динамическая побочная работа
не являются допустимыми источниками элаборационной константы.

Обычные функции/задачи не имеют модульного списка `#(...)` параметров вызова.
Обобщение делают через параметры окружающего модуля/класса, типы пакета или
разные подпрограммы. Например, статический метод параметризованного класса
может обслуживать разные типы в тестбенче.

Массивы и структуры передаются обычными аргументами. Для больших тестовых
массивов `const ref` экономит копирование, но требует соблюдения типов и времени
жизни. Не назначайте неблокирующие обновления автоматическим локальным объектам,
которые могут перестать существовать к моменту применения обновления.

Пустая подпрограмма всё равно имеет интерфейс и семантику вызова; это не
заглушка аппаратной задержки. Системные `$countones`, `$onehot`, `$clog2`,
`$isunknown` и другие средства часто заменяют самодельные вспомогательные функции;
их справочник — [приложение B](../appendices/b-reference.md).
