# 14. Параметры и generate

Параметризация меняет структуру до начала симуляции. Один и тот же модуль можно
элаборировать с разной шириной, количеством каналов и типом данных. Изменение
сигнала во время работы не может создать новый экземпляр аппаратуры.

## Значения и типы параметров

```systemverilog
module delay_cell #(
  parameter type T = logic [7:0]
) (
  input logic clk,
  input T d,
  output T q
);
  always_ff @(posedge clk) q <= d;
endmodule
```

Экземпляр с `#(.T(logic [15:0]))` хранит 16 бит. Параметр типа сохраняет
структуру интерфейса лучше, чем отдельные независимые числа ширины полей.
Значение `parameter` переопределяют в экземпляре по имени; производные размеры
вычисляют через `localparam`, чтобы пользователь не мог нарушить инвариант.

`$clog2(N)` вычисляет округление логарифма вверх. Для N=1 результат равен 0,
но `logic [-1:0]` не является вектором нулевой длины. Поэтому ширину
указателя часто задают как `(N > 1) ? $clog2(N) : 1`.
Для счётчика 0..N включительно нужно `$clog2(N+1)` бит с учётом нижней границы.
Ограничения N>0 проверяйте отдельно; отрицательные/нулевые параметры не должны
молча порождать странные диапазоны.

## Циклическая генерация

```systemverilog
module lane_registers #(parameter int N = 4) (
  input logic clk,
  input logic [N-1:0] d,
  output logic [N-1:0] q
);
  for (genvar i = 0; i < N; i++) begin : g_lane
    always_ff @(posedge clk) q[i] <= d[i];
  end
endmodule
```

`genvar` участвует в элаборации; во время симуляции здесь уже есть N процессов.
Для каждой итерации создаётся отдельная область, доступная как `g_lane[0]`,
`g_lane[1]` и так далее. Индекс генерации доступен как локальная константа
соответствующей итерации. Явные имена защищают тестбенч от нестабильных `genblkN`.

Ключевые слова `generate/endgenerate` могут группировать конструкции;
в контекстах SystemVerilog, где генерация однозначна, они не обязательны.
Не путайте это с процедурным `for`: последний исполняется при активации процесса,
хотя синтезатор тоже может развернуть его вычисление в схему.

## Условная генерация

`if` или `case` вне процедурного блока с постоянным условием выбирает ветвь
структуры. Например, параметр `USE_PIPELINE` выбирает вариант с регистром
или прямой передачей. Только выбранная ветвь становится частью элаборированной
иерархии. Но обе ветви должны удовлетворять синтаксису исходного языка.

В процедурном `if (enable)` сигнал выбирает действие уже существующей схемы.
В generate `if (HAS_PARITY)` параметр определяет, существует ли схема чётности.
Макрос `` `ifdef `` действует ещё раньше — на текст; типовая проверка исключённого
текста вообще может не происходить.

## Валидация параметров

Проверяйте не только значения по умолчанию. Обязательные случаи: минимальная
ширина, единичная глубина, неполная степень двойки, максимально поддерживаемый размер.
Производные диапазоны не должны переполнять тип параметра. Runtime `$fatal`
в `initial` даёт понятное сообщение симуляции, но не заменяет гарантированную
диагностику синтезатора: специализированные проверки параметров зависят от flow.

`defparam` — старый способ изменения параметров по иерархическому имени;
его зависимость от структуры делает сопровождение труднее. Для нового RTL
предпочтительны явные `#(.NAME(value))` на месте создания экземпляра.
