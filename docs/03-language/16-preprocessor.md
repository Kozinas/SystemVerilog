# 16. Препроцессор и единицы компиляции

Препроцессор преобразует текст до разбора типов и элаборации. Макрос не знает,
является ли его аргумент сигналом или выражением с побочным эффектом. Поэтому
функции, параметры и пакеты обычно надёжнее для семантического повторного использования.

## include и define

```systemverilog
`ifndef PROJECT_DEFS_SVH
`define PROJECT_DEFS_SVH
`define PROJECT_MAX_CHANNELS 8
`define CLAMP_HIGH(x, limit) (((x) > (limit)) ? (limit) : (x))
`endif
```

Это содержимое заголовочного `.svh`. Guard предотвращает повторное включение
в одной препроцессорной области, но не управляет глобально всеми отдельными
запусками компилятора. `` `include "file.svh" `` вставляет текст; пути поиска
задаются инструментом. Пакет с типами обычно компилируют отдельным `.sv`.

Аргументы макросов подставляются текстом. В примере `x` встречается дважды;
передача `i++` может дать неожиданные действия. Скобки защищают приоритет,
но не устраняют повторное вычисление. Многострочное определение продолжают
обратной косой чертой перед переводом строки.

## Склейка и строки

Двойной обратный апостроф склеивает части токена, например при построении
имени сигнала. Специальное макро-кавычкование позволяет включить раскрытые
аргументы в строку. Это инструменты для генерации повторяющегося текста,
а не система типов; сложные ошибки часто проще понять по выводу препроцессора.

```systemverilog
`define REG_NAME(n) reg_``n
`define AS_TEXT(x) `"x`"
// `REG_NAME(3) становится reg_3; `AS_TEXT(hello) — строкой "hello".
```

`` `__FILE__ `` и `` `__LINE__ `` раскрывают имя файла и номер строки.
Директива `` `line `` изменяет отображаемые позиции для сгенерированного кода.
В этой методичке обратные апострофы в исходниках всегда буквальные символы,
не форматирование оболочки команд.

## Условная компиляция

`` `ifdef ``, `` `ifndef ``, `` `elsif ``, `` `else ``, `` `endif `` выбирают
текст по наличию определений. `define FEATURE 0` всё равно определяет FEATURE;
обычный `ifdef FEATURE` не вычисляет арифметическое значение нуля.
`undef` удаляет одно определение, `undefineall` — определения в соответствующем
препроцессорном состоянии. В 2023 расширена запись логических условий директив;
для старых инструментов используйте традиционные вложенные проверки.

Один и тот же набор defines должен применяться согласованно к пакету типов,
RTL и тестбенчу. Если ширина структуры изменена только в одном файле,
компилируемый проект может получить несовместимые интерфейсы.

## Директивы окружения

| Директива | Назначение |
| --- | --- |
| `default_nettype` | Управляет неявными сетями; `none` обнаруживает опечатки |
| `timescale` | Единица времени и точность для последующих описаний |
| `resetall` | Возвращает настройки директив к исходным значениям; не заменяет `undefineall` |
| `unconnected_drive`, `nounconnected_drive` | Поведение неподключённых входов в соответствующей области |
| `celldefine`, `endcelldefine` | Помечают библиотечные ячейки |
| `begin_keywords`, `end_keywords` | Выбирают набор ключевых слов редакции языка |
| `pragma` | Стандартизованная оболочка и инструментальные расширения |

В новом RTL полезно начинать файл с `` `default_nettype none `` и явно
восстанавливать нужный контекст на границе проекта, если рядом сторонние исходники.
Не рассчитывайте на случайную директиву из ранее скомпилированного файла.
В 2023 `` `timescale `` внутри design element запрещена; объявления `timeunit`
и `timeprecision` делают локальное намерение точнее.
