# 18. Регистры, сброс и конвейеры

Последовательностная схема хранит состояние. В синхронной модели состояние
обновляется на выбранном фронте, а между фронтами комбинационная логика
вычисляет следующее значение. Все регистры одного домена логически принимают
новые значения одновременно; неблокирующие присваивания выражают эту модель.

## Сброс и enable

```systemverilog
module counter #(parameter int W = 8) (
  input logic clk, rst_n, enable,
  output logic [W-1:0] count
);
  always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) count <= '0;
    else if (enable) count <= count + 1'b1;
  end
endmodule
```

Асинхронный сброс реагирует независимо от такта. Синхронный сброс проверялся бы
внутри `always_ff @(posedge clk)` и действовал только на фронте. Полярность
сигнала и приоритет относительно enable являются частью интерфейса.

Асинхронное утверждение сброса удобно для быстрого перевода в безопасное состояние,
но снятие сброса должно удовлетворять требованиям recovery/removal и согласованию
в домене. Цифровая симуляция не доказывает физическую корректность снятия сброса.

Отсутствие ветви `else` у тактового процесса означает сохранение значения.
В комбинационном процессе похожая запись могла бы означать защёлку — контекст
событийного управления принципиален. Присваивание `q <= q` обычно избыточно.

## Конвейер

```systemverilog
// Фрагмент модуля; d, stage0, stage1 — векторы одинаковой ширины.
always_ff @(posedge clk) begin
  stage0 <= d;
  stage1 <= stage0;
end
```

На одном фронте `stage1` принимает старое `stage0`, а не новое `d`.
Так создаются две ступени хранения. Если отдельно идут `valid` и данные,
их задержки должны совпадать. Сброс можно применять только к valid-регистрам,
когда контракт запрещает использовать данные при valid=0; это уменьшает
ресурсы сброса, но требует последовательного соблюдения контракта.

Latency — число тактов от принятия входа до доступности соответствующего выхода.
Throughput — частота приёма/выдачи новых элементов в установившемся режиме.
Двухступенчатый конвейер может иметь задержку два такта и пропускную способность
один элемент за такт. Эти показатели не противоречат друг другу.

## Загрузка с приоритетом и конфликты

В одном процессе последнее выполненное присваивание одному регистру определяет
итог для соответствующего планирования. Однако запись «сначала инкремент,
потом при условии загрузка» менее ясна, чем явное `if/else if`.
Присваивания из разных тактовых процессов не следует использовать как
способ расставить приоритет: это несколько владельцев состояния и возможная гонка.

Enable обычно синтезируется в вход CE или мультиплексор данных. Не делайте
самодельный gated clock через `clk & enable`: изменение enable может создать
ложный импульс. Для ограничения тактирования существуют библиотечные ячейки
и рекомендации FPGA-производителя.

## Инициализация и защёлки

Начальное значение при объявлении или `initial` может поддерживаться конкретной
FPGA, но в ASIC не является универсальным описанием сброса. Укажите требуемое
поведение после питания и сверяйте с целевой технологией.

Защёлка прозрачна при активном уровне разрешения и хранит значение при закрытии.
Она может быть намеренным элементом специализированной архитектуры; тогда
используют `always_latch`, проверяют временной режим и доступность ячейки.
В учебном синхронном RTL непреднамеренная защёлка чаще означает неполное присваивание.
