# 19. Память, ROM и очереди FIFO

Объявление массива задаёт хранилище в модели, но не гарантирует получение
конкретного RAM-блока. Синтезатор распознаёт шаблон чтения, записи, тактирования
и сброса, затем сопоставляет его с ресурсами выбранной технологии.

## Простой RAM-порт

```systemverilog
module sync_ram #(
  parameter int W = 8,
  parameter int DEPTH = 16,
  parameter int AW = (DEPTH > 1) ? $clog2(DEPTH) : 1
) (
  input logic clk, we,
  input logic [AW-1:0] address,
  input logic [W-1:0] write_data,
  output logic [W-1:0] read_data
);
  logic [W-1:0] memory [0:DEPTH-1];
  always_ff @(posedge clk) begin
    if (we) memory[address] <= write_data;
    read_data <= memory[address];
  end
endmodule
```

В RTL при одновременном чтении и записи того же адреса `read_data` получает
старое содержимое: обе правые части вычисляются до NBA. Реальный RAM-блок
может иметь режимы read-first, write-first, no-change и ограничения коллизий.
Проверьте, какой режим распознал синтезатор, особенно для разных портов/тактов.
Если DEPTH не степень двойки, часть двоичных адресов недопустима; контракт должен
запрещать их или код обязан обработать их явно.

Асинхронное `assign read_data = memory[address];` описывает другой интерфейс
чтения. На FPGA он может потребовать распределённую память или регистры,
в то время как блоковая память имеет синхронный выход. Добавить регистр после
синтеза без изменения протокола нельзя: это меняет задержку.

## ROM и начальные данные

ROM можно описать через `case` адреса или константную таблицу. `$readmemh` и
`$readmemb` загружают массив из файла в симуляции; многие FPGA-flow поддерживают
их и для инициализации памяти, но пути, формат и попадание файла в проект
надо проверить. В ASIC такая запись не создаёт автоматически ROM-макрос.

Сброс всех ячеек циклом в одном такте описывает массовую запись и часто мешает
выводу специализированной RAM. Если нужно пометить буфер пустым, сбрасывайте
указатели/счётчики/valid, а не обязательно каждый бит данных. Если требуется
физическая очистка, определите отдельную многотактовую процедуру очистки.

## FIFO как контракт

FIFO сохраняет порядок принятых элементов. Для интерфейса valid/ready передача
происходит на фронте, когда оба сигнала равны единице. Источник удерживает valid
и данные до принятия. Приёмник может снимать ready, создавая backpressure.

У синхронного FIFO обычно есть массив, указатель записи, указатель чтения
и счётчик заполнения. `empty` означает count=0, `full` — count=DEPTH.
При только записи count увеличивается; при только чтении уменьшается;
при обеих передачах не меняется. События считаются по принятым операциям,
а не по одному сигналу желания `valid` или `ready`.

Для неполной степени двойки указатели должны явно переходить из DEPTH-1 в 0.
Для DEPTH=1 оба указателя постоянно равны 0, но count всё ещё различает
пустое и полное состояния. Эти два случая обнаруживают многие ошибки параметризации.

## Варианты поведения на границе

Если FIFO полон и одновременно есть чтение, можно разрешить запись замещающего
элемента в этот же такт. Можно выбрать и более простой контракт: принимать запись
только когда до фронта FIFO не был полон. Второй вариант иногда теряет один
такт на границе, зато не создаёт комбинационную зависимость ready входа от ready выхода.

Аналогично, пустой FIFO может иметь bypass (прямую передачу нового входа)
или выдавать элемент только после его сохранения. Выбранный вариант нужно
описать и проверить. Сквозной пример следующей группы использует без bypass
и без записи при полном буфере, даже если одновременно идёт чтение.
