# 21. Тактирование, CDC и переносимость

SystemVerilog задаёт функциональное поведение модели. Физическое выполнение
требует соблюдения временных ограничений элементов: setup/hold, recovery/removal,
периода такта и задержек распространения. Успешная RTL-симуляция не проверяет
их автоматически.

## Тактовый домен и временные ограничения

Домен — группа состояний, обновляемых согласованным тактом. Между регистрами
одного домена нужно уложить комбинационный путь в доступное время. Период,
входные/выходные задержки, generated clocks и исключения задаются в constraints
средствами flow, часто SDC/XDC; это не часть грамматики SV.

Не добавляйте false path, чтобы просто убрать предупреждение анализа.
Исключение должно соответствовать архитектуре передачи и быть обосновано.
Multicycle path также требует корректной логики разрешений и отдельных условий
для проверки setup/hold.

## Однобитный асинхронный уровень

```systemverilog
// Фрагмент принимающего домена, без обязательного здесь сброса.
logic sync_first, sync_second;
always_ff @(posedge destination_clk) begin
  sync_first  <= asynchronous_level;
  sync_second <= sync_first;
end
```

Две ступени уменьшают вероятность распространения метастабильности дальше.
Это не абсолютная гарантия; оценка надёжности зависит от технологии, частот,
времени разрешения и размещения. Атрибуты синхронизаторов и правила размещения
нужно брать из документации выбранного производителя.

Первую ступень обычно не используют в функциональной логике и не нагружают
несколькими независимыми потребителями. Не вставляйте произвольную комбинационную
логику между ступенями, рассчитывая сохранить ту же надёжность.

## Импульсы и шины

Короткий импульс может полностью пройти между фронтами принимающего домена.
Два триггера не гарантируют его обнаружение. Используют растяжение при
обоснованных частотах, toggle-передачу или handshake с подтверждением.

Синхронизация каждого бита многобитной шины независимо не обеспечивает
согласованного слова: биты могут быть захвачены в разные такты. Для медленно
меняющихся данных применяют протокол удержания данных с синхронизацией признака;
для потока — асинхронный FIFO с отдельной проверенной архитектурой.

Gray-код помогает передавать указатели, потому что между соседними значениями
меняется один бит, но и он требует ограничений задержек/перекоса путей.
Нельзя механически превратить синхронный FIFO этой методички в асинхронный,
заменив один такт двумя.

## Reset domain crossing

Сброс имеет собственные домены и последовательность снятия. Часто применяют
асинхронное утверждение и синхронизированное снятие отдельно в каждом домене.
Состояния протокола должны учитывать, что соседний домен уже работает или
ещё удерживается в сбросе. Без этого потеря транзакции возможна даже при
корректной синхронизации одного сигнала.

## Переносимость RTL

Разделяйте три уровня: конструкция разрешена LRM; компилятор её принимает;
синтезатор выводит требуемый аппаратный ресурс. Поддержка интерфейсов, памяти,
начальных значений и атрибутов зависит от версии инструмента и цели.
Для vendor IP храните версию, параметры генерации, модель симуляции
и необходимые ограничения рядом с интеграцией.

После изменения RTL проверяйте lint, элаборацию вариантов параметров,
функциональные тесты, отчёт синтеза и timing. Для CDC/RDC нужен соответствующий
анализ структуры и протоколов, а не только запуск случайного тестбенча.
Сведения о синтезируемом подмножестве следует сверять, например, с
[AMD UG901](https://docs.amd.com/r/en-US/ug901-vivado-synthesis/SystemVerilog-Support).
