# 23. Тестбенчи, clocking и ввод-вывод

Тестбенч создаёт входы, наблюдает выходы и сравнивает их с контрактом.
Печать значений сама по себе не является проверкой. Самопроверяющийся тест
должен завершиться успехом или ошибкой автоматически и иметь ограничение времени.

## Минимальный стенд

```systemverilog
module register_tb;
  timeunit 1ns;
  timeprecision 1ps;
  logic clk = 0;
  logic rst_n = 0, en = 0;
  logic [7:0] d = 0, q;
  enabled_register dut(.*);
  always #5ns clk = ~clk;
  initial begin
    repeat (2) @(negedge clk);
    rst_n = 1;
    en = 1;
    d = 8'hA5;
    @(negedge clk);
    if (q !== 8'hA5) $fatal(1, "Register mismatch");
    $display("PASS");
    $finish;
  end
  initial begin
    #1us;
    $fatal(1, "Timeout");
  end
endmodule
```

Этот стенд компилируется вместе с модулем из главы 01. Стимулы и проверка
на negedge удалены от рабочего posedge DUT. `!==` замечает X/Z. `$fatal`
сообщает ошибку и завершает прогон; `$finish` завершает нормальную симуляцию.
`$stop` часто переводит инструмент в интерактивный режим и неудобен в CI.

## Driver, monitor, scoreboard

Driver преобразует транзакцию в сигналы. Monitor восстанавливает транзакции
из реально принятых передач. Scoreboard сравнивает их с эталоном. Если эталон
пополняется по намерению driver, а не по фактическому handshake, тест ошибочно
ожидает данные, которые DUT ещё не принял.

Эталонная модель должна быть проще и независимее RTL. Для FIFO достаточно
программной очереди; копирование тех же указателей и формул создаёт риск
повторить один дефект в DUT и проверке.

## Clocking block

```systemverilog
// Фрагмент тестового интерфейса.
clocking cb @(posedge clk);
  default input #1step output #0;
  input ready, response;
  output valid, request;
endclocking
```

`input` здесь — сигнал, наблюдаемый тестбенчем, `output` — управляемый им.
`#1step` выбирает вход непосредственно перед тактовым событием, что даёт
согласованный снимок. Output skew задаёт планирование драйва относительно
события. Это не физическая задержка элемента.

Тестовый процесс использует `@(cb)` и доступ через `cb.request`, а не
смешивает clocking и произвольные `@(posedge clk)` на тех же сигналах.
Default clocking даёт событие для разрешённых сокращений `##N` в соответствующем
контексте. `##` в clocking-процедуре и в SVA имеют связанные с тактами,
но различные синтаксические роли.

`program` предназначен для Reactive-исполнения тестовых процессов. Он не нужен
для каждого теста: модульный тестбенч с дисциплиной clocking/событий тоже корректен.
`program` не разрешает произвольные конфликтующие драйверы и не исправляет
неверный момент наблюдения результата.

## Файлы, аргументы и диагностика

`$fopen` открывает файл, `$fclose` закрывает, `$fdisplay`/`$fwrite` пишут,
`$fgets` и `$fscanf` читают. Проверяйте handle и число успешно разобранных полей.
Для памяти используйте `$readmemh`/`$readmemb`, для текстового форматирования —
`$sformatf`. `%h`, `%b`, `%0d`, `%s`, `%p`, `%t` подходят разным представлениям.

`$test$plusargs("TRACE")` проверяет опцию запуска,
`$value$plusargs("SEED=%d", seed)` читает значение. Seed и набор параметров
надо сохранять в отчёте, иначе случайный дефект трудно воспроизвести.
`$dumpfile`/`$dumpvars` создают VCD там, где это поддерживается инструментом.
Осциллограммы помогают разбору, но не заменяют автоматическое сравнение.
