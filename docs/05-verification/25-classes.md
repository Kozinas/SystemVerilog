# 25. Классы и объектная модель

Класс описывает программный объект тестбенча: транзакцию, драйвер, монитор,
эталонную модель. Переменная класса содержит handle, первоначально `null`.
`new` создаёт объект; объявление handle само по себе объекта не создаёт.
Классы не входят в обычное переносимое подмножество RTL-синтеза.

## Поля, методы и конструктор

```systemverilog
class packet;
  rand bit [7:0] data;
  int unsigned sequence_id;

  function new(int unsigned id = 0);
    sequence_id = id;
  endfunction

  function packet copy();
    packet result = new(sequence_id);
    result.data = data;
    return result;
  endfunction
endclass
```

Поле `rand` будет участвовать в рандомизации, которая вводится в следующей главе.
Методы класса имеют автоматическое время жизни локальных переменных.
`this` обозначает текущий объект и помогает отличить поле от одноимённого аргумента.
Конструктор `new` не имеет обычного возвращаемого типа.

`packet a, b; a = new; b = a;` создаёт один объект и два handle на него.
Изменение `b.data` видно через `a.data`. Вариант `b = a.copy();` выше создаёт
отдельный объект. Если в классе есть handles на другие классы, такая копия
должна явно решить, копировать дочерние объекты или делить их.
Встроенное shallow-copy создание через `new source` также не выполняет
произвольную глубокую копию графа объектов.

## Доступ и статические члены

По умолчанию члены доступны извне. `local` ограничивает доступ классом,
`protected` допускает доступ производных классов. `static`-поле общее для
всех объектов данного класса; оно подходит счётчику выданных идентификаторов,
но может случайно связать независимые тесты.

Статический метод вызывается через `ClassName::method()` и не имеет `this`.
Метод можно объявить `extern` в классе и определить вне через квалифицированное
имя, сохранив сигнатуру. `const`-поля имеют специальные правила установки,
которые позволяют выразить неизменяемую часть объекта.

## Наследование и виртуальный вызов

```systemverilog
virtual class predictor;
  pure virtual function int expected(input int value);
endclass

class increment_predictor extends predictor;
  virtual function int expected(input int value);
    return value + 1;
  endfunction
endclass
```

Абстрактный `virtual class` нельзя непосредственно создать. `pure virtual`
задаёт обязательный метод без реализации. Виртуальный вызов через handle
базового класса выбирает реализацию фактического объекта. Без виртуальности
выбор метода не обязательно соответствует динамическому типу.

`extends` поддерживает одиночное наследование реализации. `super` обращается
к базовому классу, в том числе к его конструктору. Аргументы базового конструктора
должны быть переданы по допустимому синтаксису. Присваивание handle производного
класса базовому безопасно; обратное направление требует проверки `$cast`.
Это downcast handle, а не преобразование объекта по полям.

## Обобщения и интерфейсные классы

Класс может иметь параметры значений и типов: `class box #(type T = int);`.
Разные специализации образуют разные типы. Static-члены относятся к конкретной
специализации, что важно для общих счётчиков и фабрик.

`interface class` задаёт набор чисто виртуальных методов; класс может
`implements` несколько таких контрактов. Это не аппаратный `interface`,
не набор сигналов и не способ множественного наследования полей реализации.
Forward typedef позволяет объявить имя класса до полного определения,
например для взаимных ссылок.

В 2023 добавлены средства ограничения наследования/переопределения и
`std::weak_reference`. Слабая ссылка позволяет наблюдать объект без той же
роли удержания, что обычный handle. Эти возможности требуют режима 2023;
они не нужны для простого driver и описаны в карте обновлений главы 33.

## Связь с сигналами

Класс драйвера хранит `virtual stream_if` или другой virtual-interface handle.
Его передают из модульного окружения после создания физического интерфейса.
Так класс оперирует транзакциями, а доступ к сигналам централизован в драйвере.
Не распределяйте запись одного сигнала между несколькими независимыми объектами.
