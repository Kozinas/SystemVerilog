# 26. Случайные воздействия и ограничения

Случайный тест полезен, если генерирует допустимые транзакции, воспроизводится
и проверяет результат. Равномерное создание битов без учёта протокола часто
тратит почти всё время на бессмысленные или запрещённые комбинации.

## rand, randc и constraint

```systemverilog
class request;
  rand bit write;
  rand bit [7:0] address;
  rand int unsigned length;
  constraint legal {
    address inside {[8'h20:8'h7f]};
    length inside {[1:8]};
    address + length <= 128;
    if (write) length <= 4;
  }
endclass
```

Это декларация отношений: solver ищет значения, удовлетворяющие всем активным
ограничениям одновременно. Порядок строк не является порядком присваиваний.
Здесь широкий `length` делает арифметику суммы достаточной; при узких полях
их нужно явно расширить, чтобы переполнение не изменило смысл ограничения.

`rand` выбирает новое значение с учётом ограничений. `randc` циклически
перебирает значения своего допустимого пространства до повторения, с ограничениями
взаимодействия solver и размера типа. Это не гарантия обхода всех комбинаций
нескольких полей и не средство полного покрытия теста.

## Вызов и обработка отказа

```systemverilog
// Фрагмент initial после объявления класса request.
request req;
req = new;
if (!req.randomize() with { length == 2; })
  $fatal(1, "Unsatisfiable request constraints");
```

Неудача `randomize()` должна быть обработана: использовать прежние значения
как новые случайные данные — скрытая ошибка теста. Не помещайте вызов с нужным
побочным эффектом только внутрь отключаемого immediate assert. При выключенных
проверках такой flow может перестать выполнять нужную рандомизацию.

`std::randomize(x, y) with {...}` работает с переменными вне класса.
`$urandom`, `$urandom_range` дают процедурную случайность без solver.
У `$urandom_range` первым аргументом обычно выступает максимум, вторым минимум;
проверяйте порядок, а не переносите привычку из другой библиотеки.

## Распределения и порядок решения

`dist` задаёт веса значений и диапазонов. `:=` назначает указанный вес
каждому значению диапазона, `:/` распределяет общий вес диапазона между значениями.
Это существенно, если диапазоны разной длины.

`solve a before b` влияет на распределение решений, а не превращает
ограничение в процедурную программу и не разрешает несовместимые условия.
`soft` задаёт предпочтение, которое может быть отброшено при более сильном
конфликтующем требовании; оно удобно для значений по умолчанию в базовом тесте.
`disable soft` управляет такими предпочтениями в разрешённых контекстах.

`rand_mode` включает/выключает участие поля; `constraint_mode` — блока ограничений.
Отключённое случайное поле становится фиксированным входом для оставшихся
активных ограничений. `pre_randomize` и `post_randomize` позволяют подготовить
состояние и вычислить производные данные; не прячьте там изменение контракта.

## Массивы и последовательности

Можно ограничить `array.size()`, затем задать поэлементные условия через
`foreach`. Редукции `sum() with (...)` полезны для общей длины/суммы, но требуют
правильной ширины. `unique { ... }` в constraint задаёт различие значений;
это другой контекст, чем `unique case`.

`randcase` случайно выбирает ветвь по весу. `randsequence` описывает
грамматику случайной последовательности продукций. Они полезны для сценариев,
но не заменяют solver ограничений над всеми полями транзакции.

Seed обеспечивает воспроизводимость только при согласованном коде, инструменте,
порядке создания объектов и потоков случайности. Добавление лишнего вызова
генератора может изменить последующую трассу. Сохраняйте seed, версию симулятора,
параметры теста и ревизию исходников.
