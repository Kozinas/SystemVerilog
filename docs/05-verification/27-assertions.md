# 27. Assertions, sequences и properties

Assertion делает требование исполняемым. Immediate assert проверяет условие
при выполнении процедуры. Concurrent assertion наблюдает последовательность
значений на событиях и подходит временным свойствам протокола.
В симуляции нарушение сообщает об ошибке; в formal тот же контракт может
служить целью доказательства или ограничением окружения.

## Immediate и deferred проверки

```systemverilog
// Фрагмент тестбенча.
assert (received == expected)
  else $error("Unexpected data");
```

Ноль, X или Z в условии означают неуспех. Простая immediate-проверка видит
значения текущего выполнения и может наблюдать промежуточное состояние
комбинационной сети. Deferred-формы `assert #0` и `assert final` откладывают
оценку/сообщение по специальным правилам областей планировщика. Это не то же,
что вручную поставить `#0` перед любой проверкой.

`assert` проверяет, `assume` задаёт допущение (особенно в formal), `cover`
наблюдает достижение. Использование `assume` для свойства DUT может сделать
«доказательство» бессодержательным: вы предположили именно то, что хотели доказать.

## Базовая временная запись

```systemverilog
// Фрагмент модуля, сигналы объявлены в его интерфейсе.
property response_in_time;
  @(posedge clk) disable iff (!rst_n)
    request |-> ##[1:3] response;
endproperty
assert property (response_in_time);
cover property (@(posedge clk) rst_n && request ##2 response);
```

Для каждого такта с request начинается отдельная попытка. После него response
должен встретиться через 1, 2 или 3 такта. `|->` начинает consequent с такта
окончания antecedent; `|=>` сдвигает старт consequent на следующий такт.
Поэтому для однотактового antecedent `a |=> b` соответствует `a |-> ##1 b`.

Конкурентные проверки обычно выбирают значения в Preponed, а оцениваются
позже в Observed. Они не видят только что записанное NBA-состояние как
«значение на том же фронте». `disable iff` является условием асинхронного
прерывания попыток и не тождественно sampled условию antecedent.

## Sequences и повторения

Sequence описывает совпадение во времени, property — требование, например
импликацию между совпадениями. Их можно именовать, параметризовать и повторно
использовать. Временные интервалы задаются в тактах clocking event.

| Конструкция | Идея |
| --- | --- |
| `a ##N b`, `##[m:n]` | Задержка между совпадениями |
| `a[*N]`, `a[*m:n]` | Последовательное повторение |
| `a[->N]` | Goto-повторение до N-го истинного события |
| `a[=N]` | Непоследовательное повторение с иной допустимой точкой окончания |
| `s1 and s2`, `s1 or s2` | Совместные/альтернативные последовательности |
| `s1 intersect s2` | Совпадают начало и окончание |
| `expr throughout s` | Условие сохраняется в течение последовательности |
| `s1 within s2` | Вложенное совпадение внутри другого |
| `first_match(s)` | Выбор первого подходящего окончания |

Различия `[->]` и `[=]` особенно важны при добавлении последующего `##1`:
точка окончания определяет, относительно чего начинается следующий фрагмент.
Пустые совпадения, допускаемые повторением ноль раз, нужно анализировать отдельно.

## Sampled-value функции

`$past(x, N)` читает прежнее выбранное значение, `$stable(x)` проверяет
неизменность, `$changed(x)` — изменение. `$rose`/`$fell` смотрят переход
младшего бита аргумента; для многобитного слова это не «любое увеличение».
`$sampled(x)` полезна в сообщении об ошибке, чтобы вывести именно значение
проверки, а не уже изменившийся сигнал Reactive-области.

Полезное свойство valid/ready:

```systemverilog
assert property (@(posedge clk) disable iff (!rst_n)
  out_valid && !out_ready |=> out_valid && $stable(out_data));
```

Оно требует сохранения элемента в следующий такт после остановки. Для первого
использования `$past` нужна понятная начальная история: дополнительные
valid-флаги истории или явно оговорённое поведение после reset.

## Сильные, слабые и составные свойства

Если antecedent не возникает, implication может пройти вакуозно. Добавьте
cover на запуск сценария и на его успешное завершение. `strong` требует
завершённого совпадения там, где слабое ожидание могло остаться открытым к концу
теста. Бесконечный диапазон `##[1:$]` без анализа силы свойства способен
скрыть отсутствие ответа в конечной симуляции.

Семейства `until`, `s_until`, `until_with`, `s_until_with`, `nexttime`,
`s_nexttime`, `always`, `s_always`, `eventually`, `s_eventually` описывают
длительность и обязательность событий. `accept_on`/`reject_on` и синхронные
варианты управляют прерыванием; `iff`, `implies`, `and`, `or`, `not`,
условные свойства комбинируют требования. Их грамматику нельзя механически
заменять обычной булевой алгеброй над сигналами.

Есть локальные переменные sequence, многотактовые/многодоменные свойства,
global clocking и global sampled-value функции. Их применение требует явно
заданных событий и поддержки formal/simulator. Для повторного использования
служат `checker`, `default clocking`, `default disable iff` и `bind`.
Поддержку SVA проверяйте по конкретному инструменту; принятие синтаксиса
не доказывает, что все проверки включены в запуске.
