# 28. Функциональное покрытие

Проверка отвечает «верно ли поведение», покрытие — «какие предусмотренные
ситуации мы наблюдали». 100% покрытия не доказывает корректность: план мог
не включить существенный сценарий, а наблюдаемое событие могло быть ошибочным.

## Covergroup и coverpoint

```systemverilog
class fifo_coverage;
  covergroup occupancy with function sample(int used, bit push, bit pop);
    option.per_instance = 1;
    fill: coverpoint used {
      bins empty = {0};
      bins middle = {[1:7]};
      bins full = {8};
      illegal_bins invalid = default;
    }
    put: coverpoint push;
    get: coverpoint pop;
    actions: cross put, get;
  endgroup

  function new();
    occupancy = new;
  endfunction
endclass
```

Пример относится к FIFO глубины 8. Sample вызывают один раз на наблюдаемую
операцию с согласованным снимком count и фактических handshake. Для другого
DEPTH нужно изменить или параметризовать bins; иначе «full» потеряет смысл.

Covergroup можно выбирать по событию в заголовке или явно через `sample()`.
Явный вызов удобен для транзакций: monitor сначала распознаёт факт принятия,
потом регистрирует его параметры.

## Bins и переходы

Bin — счётчик попаданий в заданное множество. `bins low = {[0:3]};`
создаёт один bin для диапазона; `bins each[] = {[0:3]};` — набор отдельных
bins. Автоматические bins удобны для небольшого пространства, но могут
маскировать недостаточно продуманный план.

Transition bins вроде `(0 => 1 => 0)` наблюдают последовательные sampled
значения. Можно описывать повторения и wildcard-шаблоны. Это средства измерения
сценария, а не полная замена временным assertions с их правилами clocking.

`ignore_bins` исключает значения из цели покрытия. `illegal_bins` отмечает
недопустимые значения, но не является универсальной заменой assertions:
контроль ошибок и политика инструментов различаются. `iff` разрешает
выборку в заданном состоянии; он не удаляет автоматически все невозможные
комбинации из определения cross.

## Cross coverage

Cross измеряет сочетания bins нескольких coverpoints. Для двух признаков
push/pop важны четыре сочетания, особенно одновременная передача. Cross
адреса, длины, режима, состояния и типа команды может быстро создать
огромное число комбинаций, многие из которых физически невозможны.

Отбирайте значимые сочетания через `binsof`, `intersect`, `with` в допустимых
контекстах, исключайте архитектурно невозможные варианты с объяснением.
Нельзя исключать bin только потому, что генератор пока не научился его достигать.
В 2023 появились дополнительные средства управления сохранением автоматически
созданных cross bins; их поддержку надо сверять отдельно.

## Опции, экземпляры и отчёт

`option` настраивает конкретный экземпляр, `type_option` — уровень типа
covergroup. Среди задач настройки: per-instance учёт, weight, goal, at_least,
имена и комментарии. Порог попаданий определяет, сколько наблюдений достаточно
для bin, но повторение одной ситуации тысячу раз не расширяет набор сценариев.

Методы `get_coverage`, `get_inst_coverage`, `start`, `stop` помогают управлять
сбором. Слияние баз между прогонами зависит от инструмента и совместимости
модели покрытия. Сохранённый seed объясняет трассу, а сохранённая coverage-база
показывает вклад прогона в общую цель.

## План покрытия для FIFO

Измеряйте пустоту, заполненность, переход к full, переход к empty, wrap обоих
указателей, одновременные передачи, несколько тактов backpressure, сброс
непустого буфера и минимальные параметры. Функциональное покрытие дополняйте
code coverage: statements, branches, toggles, FSM — набор зависит от инструмента.

Невыполненная ветвь кода может означать пробел теста или недостижимую логику.
Невыполненный функциональный bin — пробел стимула, ошибочную модель покрытия
или нарушенный контракт. Каждый остаток требует классификации по фактам.
