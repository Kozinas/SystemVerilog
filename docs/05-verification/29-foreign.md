# 29. DPI, VPI и границы UVM

SystemVerilog может вызывать внешний код и предоставлять доступ к модели
инструментальным приложениям. Это полезно для эталонных алгоритмов, файловых
форматов и связи с окружением, но требует соблюдения ABI и правил симулятора.

## DPI-C

```systemverilog
// Объявление в модуле или пакете.
import "DPI-C" function int add_reference(input int a, input int b);
```

Соответствующая C-функция для этих двухсостоянийных целых:

```c
int add_reference(int a, int b) {
    return a + b;
}
```

Фрагменты показывают границу языка; чтобы выполнить вызов, C нужно собрать
в библиотеку способом выбранного симулятора и загрузить в прогон. Дополнительно
ограничьте диапазон входов: переполнение signed int в C нельзя бездумно
приравнивать к модульной битовой арифметике SV.

`import` объявляет внешний вызов, `export "DPI-C"` делает SV-подпрограмму
доступной внешнему коду. Импортированная функция не должна потреблять модельное
время. DPI-задачи применяются для взаимодействий, допускающих соответствующую
временную семантику через SV, по правилам DPI и реализации.

`pure` обещает отсутствие побочных эффектов и зависимости от скрытого
состояния в предусмотренном контракте. `context` нужен для взаимодействия,
которому важен контекст симулятора и обратные вызовы SV. Не назначайте эти
квалификаторы ради скорости, если функция не удовлетворяет их требованиям.

## Типы и память на границе

Для сложных интерфейсов используйте сгенерированный симулятором DPI-заголовок
и `svdpi.h`. Packed bit-векторы, четырёхсостоянийные logic-векторы, строки,
open arrays и handles имеют специальные представления. `svLogicVecVal`
передаёт две составляющие битового кодирования, необходимые для X/Z;
это не просто C `uint32_t`.

Open arrays доступны через `svOpenArrayHandle` и функции запроса границ/элементов.
Не предполагайте произвольную непрерывность, порядок индексов и layout памяти.
`chandle` переносит непрозрачный указатель, но не управляет автоматически
его освобождением. `string` на границе требует ясного владения и времени жизни.

Контекст `svScope` позволяет выбирать нужную SV-область в предусмотренных
операциях. Нельзя безопасно вызывать API симулятора из произвольного потока ОС,
если это не поддерживает документация конкретного инструмента.

## VPI и интерфейс assertions

VPI предоставляет обход объектов модели, чтение/изменение значений,
регистрацию callbacks и взаимодействие с планировщиком через стандартный API.
Это подход для трассировщиков, адаптеров и отладочных инструментов, которым
нужно обнаруживать объекты динамически. DPI обычно проще для явного вызова
известной функции с заданной сигнатурой.

С VPI важны тип handle, область callback и разрешённые операции в этой области.
Запись в read-only callback или чтение до установления NBA-значений нарушит
контракт наблюдения. Полный справочник `vpi_*`, кодов объектов и callbacks
нужен из LRM и заголовков симулятора; его нельзя заменить краткой таблицей.
Интерфейсы управления assertions предоставляют дополнительные средства
инструментального наблюдения и контроля проверок.

## UVM

UVM — библиотека классов и методология, стандартизованная отдельно как IEEE 1800.2.
Она использует классы, randomization, interfaces и другие средства SystemVerilog,
но имена `uvm_component`, `uvm_sequence`, `uvm_config_db` не являются ключевыми
словами языка. Нужны библиотека, её версия и настройки сборки.

UVM организует driver/monitor/agent, sequencer и sequences, TLM-связи,
scoreboard, фазы и сообщения. Factory позволяет заменять реализации,
configuration передаёт настройки, objections управляют завершением фаз.
Для маленького регистра прямой тестбенч проще; для семейства сложных компонентов
единая методология помогает повторному использованию. API и версии берите
из [официальной страницы Accellera UVM](https://www.accellera.org/downloads/standards/uvm).
