# 30. Примитивы, силы и пользовательские сети

RTL обычно описывает логику операторами и процессами. Для чтения netlist,
моделей ячеек и общих шин нужны нижние уровни языка: примитивы, сетевое
разрешение, силы драйверов и пользовательские сетевые типы.

## Встроенные вентили

```systemverilog
module gate_example(input wire a, b, enable, output tri y);
  wire combined;
  and u_and(combined, a, b);
  bufif1 u_driver(y, combined, enable);
endmodule
```

Для обычных логических вентилей первым терминалом идёт выход, затем входы.
`and`, `nand`, `or`, `nor`, `xor`, `xnor` поддерживают логические функции;
`buf` и `not` — буферизацию/инверсию. У buffer-примитивов с несколькими
выходами порядок иной по числу терминалов: вход последний. Не переносите
правило произвольного модуля на каждый вид примитива.

`bufif1/bufif0`, `notif1/notif0` имеют управление включением. Когда драйвер
отключён, выход Z. Массив примитивов создаёт повторяющиеся элементы для векторов.
Имя экземпляра и диапазон помогают навигации по netlist.

## Сети и разрешение

`wire` и `tri` используют обычное разрешение драйверов. `wand`/`triand`
разрешают по проводному AND, `wor`/`trior` — по проводному OR. `tri0`/`tri1`
дают слабое значение по умолчанию, `supply0`/`supply1` моделируют постоянные
питающие уровни. `trireg` моделирует хранение заряда с размером/затуханием
в соответствующих режимах; это не обычный регистр `reg`.

Силы вроде `supply`, `strong`, `pull`, `weak` участвуют в разрешении
конфликтующих драйверов. Более сильный может определить результат, равносильные
противоположные значения дают X. Сила не равна непрерывному напряжению:
это дискретная модель. `pullup`/`pulldown` создают подтягивающие драйверы.

`uwire` выражает требование одного драйвера. `interconnect` применяется
для обобщённых межсоединений по специальным правилам вывода типа и соединения;
его не следует использовать как замену любой переменной.
`alias` делает сетевые части одной связью и поддерживает двунаправленность,
в отличие от однонаправленной зависимости `assign`.

## Переключательный уровень

`nmos`, `pmos`, `cmos` и резистивные варианты моделируют управляемые
переключатели. `tran`, `rtran`, `tranif0/1`, `rtranif0/1` описывают
двунаправленное соединение. Правила передачи силы, X и Z зависят от примитива.
Такая модель полезна для специализированных библиотек, но не является SPICE
и не описывает аналоговый ток транзистора.

Задержки вентилей могут различать нарастание, спад и выключение.
Выбор мин/тип/макс и взаимодействие путей рассматриваются в следующей главе.
Для обычной FPGA-логики используйте RTL или рекомендованные vendor primitives;
транзисторные конструкции часто не поддерживаются синтезом.

## UDP: пользовательские примитивы

```systemverilog
primitive udp_and(output y, input a, b);
  table
    0 ? : 0;
    ? 0 : 0;
    1 1 : 1;
  endtable
endprimitive
```

UDP имеет скалярный выход и скалярные входы; таблица задаёт комбинационное
или последовательностное поведение. Неописанные комбинации дают X;
`?` в таблице покрывает допустимые входные состояния, а Z обрабатывается
по UDP-правилам, обычно как неизвестность на входе.

У последовательностного UDP выход объявляют хранящим состояние. Строка таблицы
содержит входы, текущее состояние и следующее состояние. `-` означает
сохранение состояния, обозначения переходов вроде `(01)`, `r`, `f`, `p`,
`n`, `*` описывают события на входах с разной точностью. Можно сочетать
уровневые условия с переходами, соблюдая ограничения таблицы.
Начальное значение задаётся допустимым способом для последовательностного UDP.

UDP — компактная таблица цифровой ячейки, но не произвольная процедура:
нет широких шин, задач и вычислительных циклов внутри таблицы.
Экземпляр создают структурно, как примитив, с правильным порядком терминалов.

## nettype

`nettype` позволяет связать тип данных сети с пользовательской функцией
разрешения. Она получает набор значений драйверов и вычисляет результат.
Это полезно для абстрактных моделей электрических соединений или смешанных
доменов данных. Функция должна соблюдать ограничения языка для разрешения;
побочные временные действия здесь неуместны.

Пользовательский nettype с `real` не превращает SystemVerilog в полный
аналоговый решатель. Для аналогового моделирования существуют отдельные
стандарты и инструменты. Поддержку UDN и синтеза проверяют независимо.
