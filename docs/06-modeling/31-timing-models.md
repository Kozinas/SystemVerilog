# 31. specify, задержки и библиотечные модели

RTL отвечает на вопрос о логической функции и последовательности тактов.
Модель ячейки дополнительно описывает время распространения и ограничения
входных событий. Эти средства важны для gate-level симуляции и чтения библиотек.

## Виды задержек

Задержка может принадлежать непрерывному присваиванию, примитиву, сети,
процедурному оператору или пути в `specify`. У этих конструкций разная
семантика планирования и фильтрации импульсов. Нельзя считать любое `#N`
идеальным транспортным проводом с одинаковым поведением.

Вентильные и непрерывные задержки обычно подавляют короткие импульсы по
инерционным правилам соответствующей конструкции. Неблокирующее присваивание
с внутренней задержкой планирует отдельное обновление выбранного значения;
оно часто используется для иной модели передачи событий. Перед моделированием
узких импульсов сверяйте точные правила LRM.

Запись `min:typ:max` предоставляет три значения задержки; какое из них
используется, выбирается настройками симуляции. Это не три параллельных
моделирования статистического разброса.

## Specify paths

```systemverilog
module timed_and(input wire a, b, output wire y);
  timeunit 1ns;
  timeprecision 1ps;
  and (y, a, b);
  specify
    specparam T_RISE = 0.2, T_FALL = 0.3;
    (a => y) = (T_RISE, T_FALL);
    (b => y) = (T_RISE, T_FALL);
  endspecify
endmodule
```

`specparam` задаёт параметры timing-модели. Путь `=>` и full-connection путь
`*>` имеют разные правила сопоставления портов. Пути могут зависеть
от состояния через `if`/`ifnone` и учитывать определённые переходы.
Это отдельная грамматика, а не произвольный процедурный `if`.

У синтезируемой логической функции `and` наличие specify не меняет булеву
таблицу. Синтез обычно не выводит из этих чисел физически гарантированную
задержку: реальные значения берутся из технологических библиотек и timing-flow.
Некоторые симуляторы требуют явного включения specify-обработки.

## Timing checks

Семейства `$setup`, `$hold`, `$setuphold` проверяют взаимное расположение
событий данных и такта. `$recovery`, `$removal`, `$recrem` относятся, например,
к асинхронному сбросу. `$width`, `$period`, `$skew`, `$timeskew`, `$fullskew`,
`$nochange` охватывают ширины импульсов, период и согласование событий.

Аргументы содержат события, ограничения, условия и иногда notifier.
Notifier может измениться при нарушении, а модель ячейки — распространить X,
показывая недостоверность состояния. Это реакция модели на нарушение,
а не физическая форма метастабильности во всех деталях.

Для импульсных путей существуют средства `pulsestyle_onevent`,
`pulsestyle_ondetect`, `showcancelled`, `noshowcancelled` и pulse limits.
Они управляют отражением отменённых/коротких импульсов; применять их следует
вместе с документацией конкретной библиотечной модели.

## SDF и back-annotation

SDF хранит задержки и timing-ограничения вне HDL. `$sdf_annotate` и настройки
симулятора сопоставляют их экземплярам netlist. Имена иерархии, пути,
версия библиотеки и единицы времени должны совпасть. Сообщение о частично
неприменённых данных аннотации означает неполную timing-модель.

Gate-level simulation помогает обнаружить проблемы запуска, X-поведения,
аннотации и временных сценариев. Статический временной анализ исследует
другие свойства и не заменяется одним динамическим прогоном. Для sign-off
нужен согласованный flow, а не самостоятельная задержка в учебном RTL.
