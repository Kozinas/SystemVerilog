# 32. Библиотеки и конфигурации

Разные библиотеки могут содержать модули с одним именем: поведенческую модель,
RTL и технологическую реализацию. Конфигурация позволяет выбрать, какие
определения образуют конкретную элаборированную иерархию.

## Library map и config

Схематический library map, пути должны соответствовать реальному проекту:

```systemverilog
library work ./rtl/*.sv;
library fast_cells ./models/fast/*.sv;
```

Конфигурация с выбором реализации одного экземпляра:

```systemverilog
config simulation_config;
  design work.top;
  default liblist work;
  instance top.u_memory use fast_cells.memory_model;
endconfig
```

`design` определяет вершину, `default liblist` — список поиска по умолчанию,
`instance` задаёт правило для конкретного пути. `cell` применяется к типу ячейки
в предусмотренной области. `use` выбирает реализацию явно, `liblist` задаёт
поиск. Выбор конфигурации в командной строке зависит от инструмента.

Это учебная иллюстрация: она не компилируется как самостоятельная схема без
модулей `top`, `memory_model` и реального library map. Не нужно создавать
фиктивную память, чтобы скрыть эти зависимости.

## Иерархические конфигурации

Конфигурация может ссылаться на другую конфигурацию с соответствующим
`:config`-обозначением. Так интегратор выбирает заранее определённую сборку
подсистемы. Правила библиотечного поиска и приоритет правил `instance/cell`
нужно читать вместе: локальное правило может изменить ожидаемый выбор реализации.

Список библиотек не является препроцессорным include path. Первый ищет
определения элементов проекта, второй — текст включаемых файлов. Путать их
особенно легко при переходе между GUI-проектом и файловой сборкой.

## Параметры и интерфейсы

Конфигурационные правила языка допускают определённые формы выбора параметров
при binding, но практическая поддержка неодинакова. Для основного учебного RTL
предпочтительна явная параметризация экземпляра `#(.W(...))`: она локальна
и хорошо читается. Конфигурация полезна для выбора реализаций, а не для скрытой
подмены размера протокола в неожиданном месте.

Замещающий модуль обязан соответствовать ожидаемому интерфейсу и временному
контракту. Совпадение имён портов не доказывает эквивалентность задержки,
сброса или режима read-during-write.

`extern module` объявляет интерфейс внешнего определения; nested-модули
ограничивают область определения. Их роль отличается от config: прототип
не выбирает библиотеку, а config не описывает поведение модуля.

## Воспроизводимая сборка

Храните файловый список, порядок пакетов, include directories, defines,
library map, верхний модуль, параметры и версию инструмента. Именно весь
этот набор определяет элаборацию. Фраза «скомпилировать все .sv» недостаточна,
если в дереве есть альтернативные реализации или несколько тестовых вершин.

Для небольшого проекта файловый список и разные top-модули часто проще
конфигураций. Когда используются config, добавьте в лог распечатку связанной
иерархии и проверьте выбор ячеек. Поддержка конфигураций компилятором не означает
их одинаковую реализацию всеми средствами синтеза.
