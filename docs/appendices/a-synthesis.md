# A. Матрица синтезируемости

Синтезируемость определяется сочетанием конструкции, способа использования,
версии инструмента и целевой технологии. Таблица — ориентир для архитектурного
выбора, а не замена перечню поддержки выбранного EDA.

| Конструкция | Обычное применение | Ограничения |
| --- | --- | --- |
| `module`, статическая иерархия | RTL | Порты/размеры должны разрешаться при элаборации |
| `parameter`, `localparam`, `generate` | RTL | Константные условия, допустимые параметры |
| `logic`, `wire`, packed-векторы | RTL | Правила драйверов, конечная ширина |
| `bit`, целые типы | RTL/тест | Не скрывать X двухсостоянийной моделью; контролировать ширину |
| `enum`, `typedef`, `struct packed` | RTL | Кодирование/типы должны поддерживаться frontend |
| `union packed` | Представления битов | Одинаковый размер обычных членов; проверить поддержку |
| Распакованные фиксированные массивы | RAM/регистры | Способ чтения/записи определяет ресурсы |
| `assign`, `always_comb` | Комбинационная логика | Полные присваивания, отсутствие петель |
| `always_ff` | Регистры | Допустимый шаблон clock/reset, один владелец |
| `always_latch` | Намеренная защёлка | Нужна поддержка и соответствующий timing-flow |
| `if`, `case`, `unique`, `priority` | Выбор логики | Обещания квалификаторов должны выполняться |
| Процедурный `for`, `foreach` | Повторяющаяся логика | Синтезатор должен ограничить и развернуть работу |
| Чистые функции | Комбинационное вычисление | Без времени и неподдерживаемой динамики |
| Задача без времени | Возможна как RTL-абстракция | Аргументы и тело должны поддерживаться |
| `interface`, `modport`, пакеты | Организация RTL | Набор возможностей зависит от синтезатора |
| `initial`, начальные значения RAM | Часто FPGA-flow | Не переносимая гарантия ASIC power-up |
| `#delay`, файловые операции | Модели/тест | Не обычные аппаратные задержки и периферия |
| Динамические массивы, очереди, ассоциативные массивы | Тестбенч | Не обычное динамическое выделение аппаратуры |
| `string`, `real`, `shortreal` | Тест/моделирование | Специальные flow возможны, обычный RTL иной |
| Классы, mailbox, semaphore | Проверка | Программные объекты симуляции |
| `randomize`, constraints, covergroups | Проверка | Не аппаратный генератор/измеритель по умолчанию |
| SVA, checker, bind | Симуляция/formal | Некоторые flow строят аппаратные мониторы отдельно |
| DPI/VPI | Связь с внешним кодом | Не синтезируемый вызов C-процессора |
| `specify`, SDF, timing checks | Gate-level модели | Не способ задать физический delay RTL |
| Силы, MOS/tran, trireg | Модели сетей | Ограниченная поддержка логическим синтезом |
| `force/release` | Отладка тестбенча | Переопределение модели, не стандартная RTL-схема |
| `config`, library map | Выбор реализации | Поддержка flow и инструментов неодинакова |

## Практический критерий

Для любой новой конструкции задайте четыре вопроса: сколько аппаратных
элементов она требует; когда они обновляются; каковы их входы и выходы;
может ли инструмент вывести этот ресурс для выбранной цели? Если ответ
«во время работы создаётся объект произвольного размера», это обычно
программная модель, а не переносимое RTL.

Синтезируемый текст может описывать чрезмерно дорогую схему. Например,
переменное деление или большой мультиплексор разрешены далеко не бесплатно.
Смотрите отчёт ресурсов и критический путь. Удалённый синтезатором сигнал
может означать оптимизацию константы, недостижимую логику или ошибку соединения.

Сверка конкретной реализации: [AMD UG901](https://docs.amd.com/r/en-US/ug901-vivado-synthesis/SystemVerilog-Support).
Инструментальное правило не следует распространять на все FPGA/ASIC.
