# C. Упражнения и ответы

Сначала предскажите результат на бумаге, затем проверяйте его кодом. Если
компилятор выдаёт предупреждение, объясните его причину до отключения.
Для упражнений на аппаратную структуру дополнительно полезна схема и отчёт синтеза.

## Ответы к главам 01–09

**01.** Без фронта и сброса `q` не меняется; при en=0 не изменится и на фронте.
Непрерывное `assign q=d` повторит изменения d после обработки событий модели.

**02.** Значения: unsigned 255, signed -1, 1. `'1` заполняет все 16 бит,
а десятичная единица после преобразования даёт `16'h0001`.

**03.** Максимум 255+255=510 требует 9 бит. Именованное соединение сохраняет
смысл после перестановки деклараций; позиционное может подключить другие порты.

**04.** NBA-пара даёт a=7, b=2. Blocking-пара — a=7, b=7.
Inactive с `#0` находится перед NBA, поэтому ожидание не является барьером NBA.

**05.** `logic [12:0] r;`, `int unsigned count;`, `wire shared_line;`.
`const`-переменная не обязательно является константой элаборации, в отличие
от подходящего parameter/localparam.

**06.** Первый сдвиг даёт `8'hC0` (-64), второй `8'h40` (64).
Максимальная сумма трёх байтов 765 требует 10 бит: расширьте каждый вход
до десяти бит перед сложением.

**07.** Размер 45 бит. При порядке valid, address, data: valid[44],
address[43:32], data[31:0]. Статический cast enum не проверяет допустимость метки.

**08.** Packed-тип имеет 32 бита. У mem четыре элемента по 8 бит (всего также 32),
но это другая организация. Для ожидаемых ответов удобна очередь транзакций.

**09.** `typedef logic signed [15:0] s16_t;` и `s16_t'($signed(raw))`.
`int'(1.8)` даёт 2, `$rtoi(1.8)` — 1.

## Ответы к главам 10–18

**10.** Неполное присваивание выражает хранение, обычно непреднамеренную защёлку.
Исправление: `always_comb begin q='0; if (enable) q=d; end`.

**11.** Обычный case выбирает первую подходящую ветвь; unique дополнительно
диагностирует нарушение исключительности. Priority сохраняет смысл приоритета
и не требует исключительности. Квалификатор не меняет сами маски.

**12.** Automatic даёт отдельные аргументы/локальные объекты активным вызовам.
Output копируется при возврате, запись через ref видна в исходном объекте во
время выполнения. У ref важны совместимость типов и lifetime.

**13.** Объявление должно быть доступно в месте использования; импорт в теле
не перемещается назад в заголовок. Bind удобен для добавления одинаковой
проверки ко всем экземплярам чужого или неизменяемого RTL.

**14.** Адресные ширины: 1, 3, 4. Счётчики: 1, 3, 5. При глубине 5
трёхбитный указатель естественно оборачивается после 7, а нужно после 4.

**15.** Источник выдаёт request/address, принимает acknowledge; приёмник наоборот.
Экземпляр интерфейса создаёт свои объекты, одинаковые имена их не объединяют.

**16.** Ifdef проверяет факт определения, а не числовое значение. Параметр
можно независимо задать каждому экземпляру, сохранив типовую и элаборационную проверку.

**17.** `logic [8:0] full; assign full={1'b0,a}+{1'b0,b};`
и `assign y=full[8] ? 8'hFF : full[7:0];`. Старший бит — unsigned overflow.

**18.** Valid проходит те же две ступени через NBA и сбрасывается в 0.
Данные при valid=0 не должны влиять на принимаемые транзакции или проверки
значимости; тогда сбрасывать их ради функциональности не обязательно.

## Ответы к главам 19–27

**19.** После операций count: 1, 2, 2, 1, 0. Пустота была до первой
операции и после последней. Одновременные принятые чтение/запись сохраняют count.

**20.** Выбор контракта должен быть явным. Для удержания done оставьте
автомат в REPORT до ack; выход done остаётся 1 всё это время. Новые start
при занятости игнорируются или запрещаются контрактом/проверкой.

**21.** При переходе 01→10 независимые синхронизаторы могут дать 00 или 11.
Для редкого слова удерживайте данные до подтверждения, а управление передавайте
согласованным handshake; стабильность шины и timing также нужно обеспечить.

**22.** Только чтение: до фронта full запрещает запись. Для варианта замещения
возможна формула `rst_n && (!full || (out_valid && out_ready))`, но она
меняет комбинационные зависимости, RTL и эталон на границе.

**23.** `q != expected` может стать X; if не выбирает ветвь ошибки.
`!==` даёт определённый ответ. Храните seed, версию симулятора, ревизию
исходников и параметры/опции запуска.

**24.** Оставшийся таймер позже ошибочно завершит успешную операцию как timeout.
Disable fork ограничивают отдельным родительским процессом, чтобы не убить
другую фоновую работу вызывающей процедуры.

**25.** Mailbox передаёт handle, обе стороны видят объект. Создавайте новую
транзакцию на передачу либо отправляйте независимую копию, включая нужные
вложенные объекты.

**26.** Например `int unsigned length`, `bit [3:0] address` и ограничения
`length inside {[1:4]}; int'(address)+length <= 16;`.
Порядок случайных вызовов, solver и код могут измениться даже при том же seed.

**27.** Для однотактового req первая проверка требует ack в том же выбранном
такте, вторая — в следующем. Без req implication проходит вакуозно;
нужны cover на запрос и завершение сценария.

## Ответы к главам 28–33

**28.** Count показывает объём, но не значения и их порядок. Нужен scoreboard.
Bin full фиксирует заполненность; cross/отдельное условие `full && in_valid`
фиксирует попытку записи, причём handshake при этом может отсутствовать.

**29.** Для известной C-функции естественен DPI. Logic имеет X/Z, для которых
одного бита bool недостаточно; нужно стандартное DPI-представление.

**30.** Равносильные 0/1 дают X; 0/Z даёт 0, 1/Z — 1. Сеть разрешает
драйверы, переменная не выполняет такого электрического разрешения записей.

**31.** `#2` — задержка модели, физический путь зависит от технологии и реализации.
При ошибке SDF проверьте scope аннотации, имена иерархии/netlist, версию библиотеки
и соответствие конкретной сборки файлу задержек.

**32.** Instance точнее выбирает одну память. Нужны файловый список, библиотеки,
include paths, defines, top/config, параметры, версия и опции инструмента.

**33.** Противоречия нет: язык шире RTL-подмножества. Нужны подтверждённая
функциональность и успешная реализация/анализ для целевой FPGA, включая
ресурсы, timing и необходимые проверки пересечений доменов.

## Практикумы с критериями приёмки

1. **ALU:** AND/OR/XOR и сложение с переносом. Полный перебор для ширины 4,
   проверка X-политики opcode, отсутствие latch, согласованная ширина результата.
2. **Конвейер:** задержка данных и valid на три такта. Сброс в середине потока,
   пустые такты, проверка точно заданной latency.
3. **FIFO:** прогоны глубин 1/3/8, wrap, full/empty, backpressure, reset непустого
   буфера, проверка порядка всех принятых элементов и автоматический timeout.
4. **Пакетный драйвер:** отдельные транзакции, mailbox, scoreboard, фиксируемый
   seed, корректная остановка процессов, отсутствие совместно изменяемых пакетов.
5. **Проверка протокола:** SVA удержания valid/data, ограниченного ответа,
   cover на активацию и завершение, аргументированные допущения окружения.

Успех практикума — выполненные критерии и объяснение результата, а не только
синтаксически принятый код. Начальная база FIFO находится в
[examples](../../examples/README.md).
