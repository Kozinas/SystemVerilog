Дата проверки ссылок и изменяемых сведений: **2026-09-23**. Изложение и учебные

## Как разрешать сомнения

Для точной семантики сначала найдите конструкцию в IEEE LRM, затем проверьте
errata/разъяснения и документацию конкретного инструмента. После этого создайте
минимальный пример с понятным ожидаемым результатом. Принятие примера компилятором
не делает расширение производителя частью стандарта.

Для синтеза дополнительно задайте целевую технологию, версию, атрибуты и
ограничения. Изучите отчёт выведенных примитивов, число регистров, RAM/DSP
и предупреждения. Для временной семантики запишите области выбора/обновления
и проверьте трассу событий, а не только итоговую картинку.

Нормативный стандарт большой: полная BNF, правила редких комбинаций типов,
все таблицы переключательных примитивов и API VPI требуют обращения к оригиналу.
Методичка даёт учебную последовательность, рабочие модели и указатели на эти
области, не пытаясь заменить все таблицы LRM сокращёнными пересказами.

## Обновление методички

Новая дата документации EDA не обязательно означает новую редакцию языка.
При обновлении проверяйте отдельно карточку IEEE, возможности compiler frontend,
runtime симулятора и синтезатора. Записывайте конкретные версии в отчёт
проверки, обновляйте примеры и пересобирайте PDF из исходных глав.
Непроверенное изменение нельзя обозначать как подтверждённую совместимость.
